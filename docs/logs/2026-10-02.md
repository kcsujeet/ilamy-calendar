# Development Log - 2026-10-02

## Changes

- **[vertical grid navigation]** (#300): Moving a week in a vertical time grid no longer remounts every cell, which made a 15-minute resource week take seconds to navigate.
  - Cause, from a CPU profile of three week navigations: about half the time was `DroppableContainersMap` in `@dnd-kit/core`. Every `RegisterDroppable` and `UnregisterDroppable` copies the whole container map (`core.esm.js:2628`, `:2673`, v6.3.1), so N droppables cost O(N²) to register.
  - Navigation paid it twice. The column keys and the cell keys inside a column both carried the column id, which carries the date, so React remounted all cells. The droppable id carried the date too, and `useDroppable` re-registers when its id changes (`useEffect(..., [id])`), so even a kept cell re-registered.
  - Fix: column and cell keys are positional, and `DroppableCell` takes its droppable id from `useId()`. The drop still reads the date from `data`, which `useDroppable` keeps in a ref refreshed every render (`useLatestValue`).
- **[keys]**: Removed `keys.droppable.dayCell` and the `id` prop of `DroppableCell`; nothing reads a droppable id other than dnd-kit itself.

  - `HorizontalGridRow` keyed flat cells by `col.day.toISOString()`, grouped columns by `col.id` (which carries the date) and the cells inside a group by `day.toISOString()`. - **[grid cell dialog]** (#300): only a cell that draws events mounts `AllEventDialog`. Every time-grid slot (`shouldRenderEvents={false}`, `vertical-grid-col.tsx`) mounted a closed one: Radix dialog state plus a full calendar-context subscription, in each of thousands of slots, for a dialog whose only opener (the "+N more" button) those slots never render.
  - Found by a profiling pass over production builds; the gain below is my own re-measurement, not the agent's.
  - Production builds, 6 rooms, before → after: resource week vertical 15m "next" Chromium 128 → 95 ms, Firefox 185 → 117 ms; load Chromium 460 → 375 ms, Firefox 804 → 583 ms. Week 15m "next" Chromium 47 → 31 ms. Month and the horizontal grids unchanged: their cells draw events and keep the dialog.
  - Not unit-tested directly: a closed dialog leaves no DOM, and Bun's `mock.module` cannot be undone (`mock.restore()` "does not reset modules overridden with `mock.module()`", https://bun.com/docs/test/mocks), so mocking it would leak into the month dialog tests. What must not break is pinned instead: the existing unit tests that open the dialog (`month.test.tsx`, `grid-cell-spacing.test.tsx`) and a new e2e spec that opens it from "+5 more" and finds all seven events.
- Remaining opportunities from the profile, not taken here: recurrence expanded once per column with seven timezone setters per occurrence; per-cell droppables re-rendering the grid on every drag move; context consumers re-rendering on any context change.

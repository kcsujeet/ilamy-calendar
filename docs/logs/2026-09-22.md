# Development Log - 2026-09-22

## Changes

- **[scroll-time]**: Changing `scrollTime` on a mounted calendar now scrolls to the new hour straight away. `useScrollToTime` dedupes its scroll so ordinary re-renders leave the user's scroll alone, but the dedupe key was only `${view}-${date}`, so a new `scrollTime` was ignored until the next navigation. The key now includes `scrollTime`. FullCalendar reapplies a changed `scrollTime` immediately.
- **[e2e harness]**: The harness re-reads the URL on `popstate`, and `setSettings(page, …)` changes settings on the mounted calendar. Navigating can't reproduce a runtime prop change, because the calendar would remount with the new value.
- **[scroll-to-now]** (#285): New `scrollToNow` prop (default `false`). Every scrolling grid opens on the cell that holds the current moment: the current hour in time grids, and today's column or row in resource month and daily resource week, in both orientations. It only applies while now is on screen. Otherwise it falls back to `scrollTime`, or to the range start. Like `scrollTime`, it is reapplied on range change and when the prop changes, not as the clock moves. FullCalendar has no such option: measured on Scheduler 6.1.21, `resourceTimelineMonth` opens at range start + `scrollTime`, so today is off screen by default. Its users reach today by setting `scrollTime` themselves or with `validRange`. The rules are stated in the prop's JSDoc.
- **[scroll-to-time]**: The hook finds "now" by comparing instants against each droppable cell's `data-start`/`data-end`, leaving out `data-all-day` cells. Only the vertical resource grids put their all-day row inside the scroll area. On a range without now and with no `scrollTime` target, it scrolls back to the start rather than keeping the previous range's offset. Horizontal grids now run the hook for every resource grid, not only hour grids. Vertical grids run it for every grid with rows. Day grids have no `data-hour` rows, so `scrollTime` still finds nothing there.

## Notes

- Revert-proofed: with the old key, the new unit test and both e2e cases fail.
- The e2e hours are 06 → 09 on purpose. At the pinned viewport the resource timeline has about 10 columns of scroll room, so 12:00 is clamped by the browser and would never line up. Near the end of the day, clamping is expected behaviour, not a bug.
- Next: #285 (day-axis horizontal resource views should scroll to today).
- scrollToNow revert-proofs: disabling the now target, the reset to start, the all-day exclusion, and the flag in the dedupe key each fail both a unit test and an e2e spec.
- I first gated `scrollTime` to hour grids on the belief that the day-row gutter tags every row `data-hour="00"`. A probe showed day grids have no `data-hour` at all, so the gate protected nothing and was removed.
- With `slotDuration` < 60 the target is the slot containing now, not the top of its hour, so it can sit up to 45 minutes below the hour.
- Tested by the maintainer across the demo's resource views. Near the end of the day or month, now stops short of the edge because the browser caps the scroll; FullCalendar does the same. Kept as is (centring was considered and declined) and noted in the JSDoc.

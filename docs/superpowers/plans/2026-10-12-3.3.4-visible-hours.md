# 3.3.4 Visible hours (`slotMinTime` / `slotMaxTime`) Implementation Plan

> TDD (superpowers:test-driven-development). Part of `docs/roadmap.md`, release 3.3, item 3.3.4.
> Closes the long tail of kcsujeet/ilamy-calendar#7, #40, #50, #86.

**Goal:** Consumers choose the clock range a time grid shows, independently of business hours.

## The standard (FullCalendar v7.1.1 source, `packages/preact/src/`)
- Defaults `'00:00:00'` / `'24:00:00'`; `slotMaxTime` is exclusive (`options.ts:499-500`).
- Each day column's range is `date + slotMinTime` to `date + slotMaxTime` (`common/day-cols.ts:60-61`).
- Events outside the range produce no segment; partly-outside events are clipped (`timegrid/DayTimeColsSlicer.ts:7-22`,
  `timegrid/components/util.ts:51-59`); a clipped event still shows its real start/end time text
  (`component-util/event-rendering.ts:331-345`).
- Day grids (month) ignore it (`timegrid/index.ts:12`, `usesMinMaxTime`).
- Wall-clock slots on DST days: always the same number of slots (`vanilla-tests/src/date-selection/dst-selection.ts`).
- `scrollTime` before `slotMinTime` scrolls to the top (fraction clamped, `TimeGridLayout.tsx:285-296`).
- Business hours are clipped to the window, not adjusted (`TimeGridView.tsx:75-90`).
- The now indicator shows only inside the window (`TimeGridLayoutNormal.tsx:460-462`).

## Decisions (record in TSDoc / docs)
- Accept `'HH:mm'` (and `'HH:mm:ss'`) between `'00:00'` and `'24:00'` only. FullCalendar allows a max past 24:00
  (overflow into the next day) and a negative min; **cut** for simplicity (it makes one event render in two columns).
  An invalid value (unparseable, out of range, or max ≤ min) falls back to the defaults and logs one
  `console.warn` naming the prop.
- `hideNonBusinessHours` keeps working: it narrows the visible window to business hours **within**
  `slotMinTime`–`slotMaxTime` (intersection). With neither set, rendering is byte-for-byte today's.
- Applies to every hour grid: day, week, vertical resource day/week, and the horizontal resource hour timeline
  (hourly granularity). Not month, year, agenda, or `weekViewGranularity='daily'`.

## API
```ts
/** First visible time in hour grids, 'HH:mm'. @default '00:00' */
slotMinTime?: string
/** End of the visible time in hour grids, exclusive, 'HH:mm' up to '24:00'. @default '24:00' */
slotMaxTime?: string
```

## Where (verify): `features/calendar/utils/view-hours.ts` (`getViewHours` builds the hour columns/rows — read it and
its tests first; `docs/time-grid.md` explains DST handling), the props/types/context flow alongside existing
`hideNonBusinessHours`, the layout clipping in `utils/layout/vertical.ts` and the horizontal layout, the
current-time marker, scroll-to-time. Harness query params `slotMinTime`, `slotMaxTime` in
`apps/e2e/src/harness-config.ts`.

## Tests first
Unit: `getViewHours` with min/max (08:00–18:00 → 10 hourly rows; with 30-min slots → 20); invalid values fall back
+ warn once; intersection with `hideNonBusinessHours`; DST day in America/New_York keeps wall-clock rows; an event
07:00–09:00 is clipped to start at the top with its time text still "7:00 – 9:00"; an event entirely before min
renders nothing; layout positions within the window.
e2e (real UI): week view `&slotMinTime=08:00&slotMaxTime=18:00` shows first label 8 AM and last row 5 PM; a drag to the
last row lands at 17:xx; now line hidden when "now" is outside the window (the harness pins 09:00Z — use a window
that excludes it); horizontal resource day hour timeline honours it; `scrollTime` before min scrolls to top; existing
specs without the params unchanged.

## Global constraints
No breaking change; configured dayjs only; `.at()`, no `!`, no `any`, named exports, name every condition; unit AND
e2e first; revert proof; docs (`docs/time-grid.md`, `docs/types-and-interfaces.md`, website props page,
`docs/api-parity-checklist.md` tick). Public text never frames this as parity with another library; cite FullCalendar
for specific behaviour with file:line. No dev log, no CHANGELOG.

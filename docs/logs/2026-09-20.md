## Changes (review pass on PR #283)

Ran the repo's `code-review` skill over the PR: seven reviewer agents, one per
reference file. **All seven returned FAIL.** What they found, and what changed.

### Two real defects, both in the PR's headline feature

- **[drag and drop] fix**: The grab offset was never applied. `readGrab` read
  `active.rect.current.initial` at `onDragStart`, where dnd-kit has not measured
  yet and it is **null**, so `calculateGrabOffset` bailed to `NO_GRAB_OFFSET`
  every single time and the event silently re-anchored to its own start. The
  unit tests missed it because they hand the function a rect. Measured in the
  browser (`PROBE grabOffset {"minutes":0,"days":0}, initialRect: null`); the
  rect is populated by the first `onDragOver`, which is also the first moment
  the offset is needed. Now measured there, via `resolveGrabOffset`.
- **[drag and drop] fix**: On the horizontal axis the grabbed DAY was derived
  from elapsed time, but a month row draws whole, equal day columns. The two
  agree only for a midnight-aligned span, which every existing fixture was. For
  a timed span the pointer crosses into the next day's minutes while still
  inside the previous day's column, and the drop lands a day out. `Jan 1 09:00
  -> Jan 4 17:00` was wrong across ~11% of its width. Now read from the column.
- **[drag and drop] fix**: `keptTimeOfDay` built the moved time with
  `.hour()/.minute()` setters, which hold the clock face but carry the SOURCE
  day's UTC offset. Landing on a spring-forward day serialised an hour late
  (grid shows 10:00, consumer gets `15:00Z`, true New York 10:00 is `14:00Z`).
  Measured, then rebuilt from a zoneless string, which the configured dayjs
  anchors in the target zone.

### Regression I introduced and the review caught

- **[drag and drop] fix**: `COMPARED_PROPS` excluded `style` on the stated
  grounds that "the bar reads its placement from the wrapper element". False for
  `AllEventsDialog`, which passes the bar's whole height through `style`, so a
  changed `eventHeight` was swallowed there. `style` is now compared by value,
  which keeps the memo working for the layers (they rebuild an equal object
  every render) while letting a real change through.

### Lint gap that let 12 dead symbols reach CI

- **[tooling]**: `noUnusedImports` / `noUnusedVariables` are **errors** now, not
  warnings, so CI fails on them. The extraction of the events layers left 11
  dead imports and one dead context subscription, and nothing caught them:
  `biome check --diagnostic-level=error` filters warnings out and tsconfig has
  no `noUnusedLocals`. `.astro` is excluded from both rules, per Biome's own
  guidance for its partial `.astro` support; a blanket autofix over `apps/`
  stripped a used `MainLayout` import and renamed a used variable before that
  exclusion existed (124 type errors, reverted).

  invisible to unit tests that construct their own inputs, and the first e2e

  TEXT inside the bar rather than the element spanning the day columns. Each

# Development Log - 2026-11-09

## Changes

- **[horizontal layout]**: A cell's event list and hidden count now come from the same column span its bar is placed with (PR #389 review). Before, the lists came from `bucketEventsByColumn` (instant bounds) while placement used the span's wall-clock columns, and the two disagreed on a day the clocks change. `hiddenCount` is counted up where an event has no bar, so the `Math.max(0, …)` clamp is gone.
- **[horizontal layout]**: One placement loop and one sort (`sortForPlacement`: by start, then longer first; on a day axis day-spanning events before single-day ones). `sortSingleUnit` and the split lists are removed.
- **[cells]**: `useProcessedWeekEvents` keys cell layouts by the column's `Dayjs` instance instead of its ISO instant. `GridCellBody` shows events whenever it is handed a layout.
- **[renames]**: `findMultiUnitSlot` → `findRowSlot`, `MultiUnitSlot` → `RowSlot`, `Range` → `ColumnRange` (clashed with the DOM `Range`). `MINIMUM_BAR_COLUMNS` documents where 0.4 comes from.
- **[cleanup]**: Removed `bucketEventsByColumn` and `keys.col.events`, which had no caller left.
- **[e2e]**: Added a spring-change spec. Dropped seven packing cases that only repeated `horizontal.test.ts`.
- **[docs]**: `docs/performance.md`, `docs/time-grid.md` and `docs/hooks-and-context.md` describe `columnLayouts`/`precomputedLayout` instead of `columnEventsMap`/`precomputedEvents`. Retired `2026-10-08.md` and `2026-10-10.md` to keep ten logs.

- Retraction of the review's browser description: at the PR head the browser did not show "+1 more" beside a lone bar. The hook's map was keyed by ISO instant, the skipped column and the 03:00 column share an instant, and the later column's layout overwrote the earlier one. The visible symptom was the reverse: when the 03:00 column really overflows, its "+1 more" was drawn twice, once in the skipped column. The e2e spec (Playwright `timezoneId` and `tz` both America/New_York) asserts exactly one button; it failed with 2 before the fix.
- On the autumn change day the PR head also drew a bar in the first 01:00 hour without listing the event in that cell's overflow list. The span-derived list includes it. Found by the differential run below; no dedicated test yet beyond the random comparison.
- Differential run against the PR-head layout, 18,000 random rows (UTC and New York, both 2025 change weeks, hidden days, caps 0 to 5). Hour axis: all placements identical; cell lists and counts differ only on the two change days, as intended. Day axis (month rows): cell lists and counts identical; placements differ in 24 of 9,000 rows, every one containing two events with the same start and different ends.
- That day-axis difference is deliberate and is the only month placement change: single-day events with the same start are now ordered longer first (they kept input order before), because one sort serves both groups. Pinned by "puts the longer of two single-day events with one start on the upper row".

# Development Log - 2026-10-08

## Changes

- **[vertical day grids, #322]** All-day events were never drawn in the vertical resource month view, nor in the vertical resource week view at daily granularity. Both are vertical grids whose rows are whole days (`gridType: 'day'`), and both have no all-day row (`view-renderer.tsx` builds one only for hour grids). Yet `useProcessedDayEvents` and `layoutVertical` each dropped every all-day event, on the assumption that an all-day row would draw them. Now `layoutVertical` alone decides: a time grid (hour or minute rows) leaves all-day events to its all-day row, as FullCalendar's time grid does (`AllDaySplitter`, `timegrid/src/DayTimeColsView.tsx:27`, v6.1.21), and a day grid draws them like any other event, as FullCalendar's day grid does (`daygrid/src/DayTable.tsx` has no all-day split, v6.1.21). The hook's duplicate filter is gone. The existing day-grid placement was already right: measured in the browser, the bar runs from its first day's row to where its exclusive end's row starts.
- **[drag, all-day kind]** Found while pinning the above, and already on `main`: dragging an all-day event within a month or resource day grid turned it into a timed event. Those cells report `allDay: false` with no hour (`GridCell`'s default), and `calculateDropTimes` read `false` as "a timed-only cell". It now follows FullCalendar: a drop changes an event's kind only when it crosses between an all-day area and a timed one (`interaction/src/interactions/EventDragging.ts:450`, v6.1.21). A time slot makes it timed, an all-day cell makes it all-day, and a whole-day cell keeps the event's own kind. A timed event dropped on a month cell still keeps its clock.
- **[drag mirror]** Found while testing the demo: dragging an all-day event on a vertical day grid showed a time range on the mirror ("12:00am – 12:00am"), since no all-day event had reached that mirror before. `VerticalDragPreview` now prints the time only for a timed event, per FullCalendar: "Events that are all-day will never display time text anyhow" (https://fullcalendar.io/docs/displayEventTime). The resting bars already showed no time.
- **[e2e harness]** `event-state` now publishes each event's `allDay`, so a spec can tell an all-day drop from a timed one at midnight. That gap is why the drag bug went unnoticed.

ilamy Calendar uses a **framework-agnostic CSS styling and `--ilamy-*` token contract** across React, Vue, Svelte, Solid, Angular, and Vanilla DOM with **zero Tailwind, zero `@radix-ui/*`, zero `@dnd-kit/*`, and zero `@mui/material` runtime component dependencies**.

## Framework-Agnostic Styling & Token Mappers

Everything in this section works identically across React, Vue, Svelte, Solid, Angular, and Vanilla DOM.

### Default: Layered CSS (`@ilamy/calendar/styles.css`)

Import `@ilamy/calendar/styles.css` once in your app — **no Tailwind installation or `@source` directive is required**:

```ts title="main.tsx"
import '@ilamy/calendar/styles.css'
```

If you use Tailwind CSS v4, shadcn/ui, or Base UI, import it **before** `@import 'tailwindcss';` so Tailwind utilities sit in a higher cascade layer:

```css title="globals.css"
@import '@ilamy/calendar/styles.css';
@import 'tailwindcss';
```

#### Design Tokens & shadcn/Base UI Auto-Bridging

Inside `@layer ilamy.base`, `[data-ilamy-root]` reads `--ilamy-*` tokens that automatically fall back to your page's shadcn/Tailwind variables (`--background`, `--foreground`, `--card`, `--muted`, `--muted-foreground`, `--border`, `--primary`, `--primary-foreground`, `--destructive`, `--radius`, `--font-sans`, and `.dark`), with clean light/dark defaults when no theme is present:

| Token | Bridges shadcn var | Purpose |
|---|---|---|
| `--ilamy-bg` | `--background` | Calendar and cell background |
| `--ilamy-fg` | `--foreground` | Primary text color |
| `--ilamy-surface` | `--card` | Header / resource-header / all-day surface |
| `--ilamy-muted` | `--muted` | View switcher track, hover & non-business tint |
| `--ilamy-muted-fg` | `--muted-foreground` | Secondary labels & outside-month text |
| `--ilamy-border` | `--border` | Grid borders & button borders |
| `--ilamy-primary` | `--primary` | Today badge, active primary buttons, default event bars |
| `--ilamy-primary-fg` | `--primary-foreground` | Text on primary surfaces |
| `--ilamy-danger` | `--destructive` | Current-time indicator |
| `--ilamy-radius` | `--radius` | Border radius for controls, inputs & event bars |
| `--ilamy-font` | `--font-sans` | Root font family |

Override any `--ilamy-*` token on `[data-ilamy-root]` or a wrapper element to theme the calendar without writing component overrides. This auto-bridging works out of the box with Base UI, Radix, React Aria, shadcn-vue, and shadcn-svelte.

### Slot Overrides (`[data-ilamy-slot="..."]`)

All built-in rules in `@layer ilamy.base` and `@layer ilamy.theme` are wrapped in `:where(...)` (zero specificity) inside CSS layers. Any normal selector targeting `[data-ilamy-slot="..."]` overrides them cleanly **without `!important`**:

```css
[data-ilamy-slot='event-bar'] {
  border-radius: 9999px;
  font-weight: 600;
}

[data-ilamy-slot='cell'][data-non-business='true'] {
  background-color: #f9fafb;
}

[data-ilamy-slot='dialog'] {
  border-radius: 0.75rem;
}
```

Semantic slots include `root`, `header`, `toolbar`, `nav-group`, `arrow-group`, `nav-button`, `view-switcher`, `view-button`, `grid`, `grid-scroll`, `month-header`, `day-header`, `resource-header`, `all-day-row`, `grid-row`, `cell`, `event-bar`, `now-indicator`, `more-link`, `dialog`, `popover`, `input`, `textarea`, `select`, and `checkbox`.

### Structural-Only CSS, `unstyled`, and `slotProps`

`@ilamy/calendar/styles.css` combines two separate CSS layers that you can also import individually:

- `@ilamy/calendar/styles/base.css` (`@layer ilamy.base`) — structural layout geometry only (flex/grid layout, sticky headers/gutters, and scrolling).
- `@ilamy/calendar/styles/theme.css` (`@layer ilamy.theme`) — default visual theme tokens and appearance rules.

For fully custom visual chrome while keeping structural layout, import `@ilamy/calendar/styles/base.css` and/or pass `unstyled` with `slotProps`:

```tsx
import { IlamyCalendar } from '@ilamy/calendar/react'
import '@ilamy/calendar/styles/base.css'

<IlamyCalendar
  events={events}
  unstyled
  slotProps={{
    root: { className: 'my-calendar' },
    header: { className: 'my-header' },
    cell: { className: 'my-cell' },
    eventBar: { className: 'my-event' },
    resizeHandle: { className: 'my-resize-handle' },
  }}
/>
```

### StyleX (`@ilamy/calendar/styles/stylex`)

`@ilamy/calendar/styles/stylex` is a **pure token and StyleX slot mapper** (zero React or UI-library dependency). It exposes `--ilamy-*` token presets (`createStylexCalendarTheme`, `stylexCalendarTheme`, `stylexCalendarDarkTheme`) and helpers (`stylexSlot`, `createStylexSlotProps`) for merging compiled `stylex.props(...)` outputs across React, Vue, Svelte, Solid, Angular, and Vanilla DOM:

```tsx
import * as stylex from '@stylexjs/stylex'
import { IlamyCalendar } from '@ilamy/calendar/react'
import { createStylexCalendarTheme } from '@ilamy/calendar/styles/stylex'
import '@ilamy/calendar/styles.css'

const styles = stylex.create({
  eventBar: { borderRadius: 9999 },
})

const stylexTheme = createStylexCalendarTheme({
  mode: 'light',
  slots: { eventBar: stylex.props(styles.eventBar) },
})

<IlamyCalendar events={events} {...stylexTheme} />
```

### Material UI Tokens (`@ilamy/calendar/styles/mui`)

`@ilamy/calendar/styles/mui` exports pure `createMuiCalendarTheme(theme)`, which reads a MUI `Theme` object's palette, typography, and shape directly into `--ilamy-*` CSS tokens. It ships **zero `@mui/material` runtime components**, so it works in React or alongside CSS variables in any framework:

```tsx
import { useTheme } from '@mui/material/styles'
import { IlamyCalendar } from '@ilamy/calendar/react'
import { createMuiCalendarTheme } from '@ilamy/calendar/styles/mui'
import '@ilamy/calendar/styles.css'

export function MuiCalendar({ events }) {
  const theme = useTheme()
  const muiTokens = createMuiCalendarTheme(theme)

  return <IlamyCalendar {...muiTokens} events={events} />
}
```

Outside React (for example in Vanilla DOM, Vue, Svelte, Solid, or Angular), pass any MUI-shaped theme object directly to `createMuiCalendarTheme(theme)` and apply the returned `slotProps` / CSS variables to the calendar.

## Custom Component Libraries (Base UI, Radix, React Aria, MUI)

Out of the box, `@ilamy/calendar` renders built-in dialogs, popovers, inputs, selects, and checkboxes using semantic native HTML elements (`<dialog>`, `<button>`, `<input>`, `<select>`, etc.) styled by `@ilamy/calendar/styles.css` — with **zero `@radix-ui/*`, zero icon packs, zero CVA, and zero `@mui/material` runtime components**.

Instead of primitive wrapper props, `@ilamy/calendar` keeps styling synced automatically through `--ilamy-*` CSS variables and token mappers, while letting you plug in your own dialog, form, header, event, resource, or overflow UI via custom renderers (`renderEventForm`, `headerComponent` / `renderHeader`, `renderEvent`, `renderResource`, `onMoreEventsClick`). In `@ilamy/calendar/react`, custom UIs mount cleanly through React portals inside the shared DOM renderer.

For example, to use a Base UI or shadcn/ui dialog and form while keeping calendar tokens synced automatically:

```tsx
import { IlamyCalendar } from '@ilamy/calendar/react'
import '@ilamy/calendar/styles.css'
import { Button } from '@/components/ui/button'
import { Input } from '@/components/ui/input'
import {
  Dialog,
  DialogContent,
  DialogHeader,
  DialogTitle,
} from '@/components/ui/dialog'

export function CalendarWithCustomForm({ events }) {
  return (
    <IlamyCalendar
      events={events}
      renderEventForm={({ open, onClose, selectedEvent, onAdd, onUpdate, onDelete }) => (
        <Dialog open={open} onOpenChange={(next) => !next && onClose()}>
          <DialogContent>
            <DialogHeader>
              <DialogTitle>
                {selectedEvent?.id ? 'Edit Event' : 'New Event'}
              </DialogTitle>
            </DialogHeader>
            {/* Render your Base UI, Radix, React Aria, or MUI form fields here */}
            <Input defaultValue={selectedEvent?.title ?? ''} />
            <Button onClick={onClose}>Close</Button>
          </DialogContent>
        </Dialog>
      )}
    />
  )
}
```

Use `headerComponent` / `renderHeader`, `renderEvent`, `renderResource`, and `onMoreEventsClick` in the same way to swap in custom toolbars, event cards, resource headers, or overflow popovers from any UI library.

## Headless Core (`@ilamy/calendar`)

Building a completely custom calendar UI? Import the zero-framework, zero-CSS engine directly from `@ilamy/calendar`:

```ts
import {
  createCalendarController,
  buildMonthViewModel,
  buildTimeGridViewModel,
  isRangeWithinBusinessHours,
} from '@ilamy/calendar'

const controller = createCalendarController({
  events,
  timezone: 'America/New_York',
  initialView: 'week',
})
```

## Cells During a Drag

While an event is dragged over the calendar, the grid wrapper carries `data-dragging="true"`. Day cells and time slots use it to suppress hover tints during drags.

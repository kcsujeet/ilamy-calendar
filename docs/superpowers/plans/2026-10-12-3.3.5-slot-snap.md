# 3.3.5 Slot and snap sizes Implementation Plan

> TDD (superpowers:test-driven-development). Part of `docs/roadmap.md`, release 3.3, item 3.3.5.
> Closes kcsujeet/ilamy-calendar#101 (15-minute snapping in the horizontal resource day view) and #138.

**Goal:** Any sensible slot size, and a snap size for drag, resize and drag-to-create that can be finer than the
slot, in every hour grid including the horizontal resource timeline.

## The standard (FullCalendar v7.1.1 source, `packages/preact/src/`)
- `slotDuration` default 30 min for time grids (`timegrid/index.ts:14`); any Duration; no divisibility validation
  (a non-divisor overshoots the last row, `timegrid/time-slat-meta.ts:36-50`).
- `snapDuration` has no default and falls back to `slotDuration` (`TimeGridCols.tsx:163`); if
  `slotDuration / snapDuration` is not a whole number, snap resets to `slotDuration` (`TimeGridCols.tsx:162-172`).
- Snap drives dragging, resizing and selecting (the hit's start is the snapped time within the slot).

## Decisions (record)
- `slotDuration?: number` (minutes). Widen the existing `SlotDuration` type (`15 | 30 | 60`) to `number` without
  breaking the existing literal values. ilamy draws hour rows with sub-slot lines, so accept **divisors of 60**
  (1, 2, 3, 4, 5, 6, 10, 12, 15, 20, 30, 60). Anything else falls back to 60 and logs one `console.warn` naming the
  prop. Existing 15/30/60 rendering must stay byte-identical. Cut: slots longer than an hour (record the cut).
- `snapDuration?: number` (minutes), default = `slotDuration`; if it does not divide `slotDuration`, fall back to
  `slotDuration` silently (convention). Applies to drag move, resize (3.3.3's `calculateResizeTimes`) and the
  drag-to-create plugin's selection, in vertical grids AND the horizontal resource hour timeline.
- `slotHeaderInterval` (v7 name; v6 `slotLabelInterval`): **cut** for 3.3 — ilamy labels every hour row and rows are
  hourly; record the cut in the roadmap row.
- #101 core: in the horizontal resource timeline today, find whether columns are whole hours with no sub-hour
  position. If so, snapping within an hour cell must come from the pointer's position inside the cell (the vertical
  grid already does sub-hour slots — reuse its approach if it fits; read `docs/time-grid.md` and the grab-offset /
  drop-time code). Drop and resize then land on the snapped minute.

## Tests first
Unit: slotDuration validation (each divisor ok, 7/45/90 fall back + warn once); snapDuration fallback when it does
not divide; drop-time and resize-time snapping at snap 5/15 with slot 30/60; horizontal timeline sub-hour snap math;
DST day (America/New_York 2025-03-09) snapping stays on wall-clock minutes.
e2e: `&slot=20` renders 3 sub-rows per hour; `&slot=60&snapDuration=15` drag lands on :15/:45 in week view; horizontal
resource day `&snapDuration=15` drag and resize land on quarter hours (#101's case); drag-to-create with snap;
existing slot=15/30/60 specs unchanged.

## Global constraints
No breaking change (existing `slotDuration={15|30|60}` identical); configured dayjs only; no `!`, no `any`, `.at()`,
named exports, name every condition; unit AND e2e first; revert proof; docs (`docs/time-grid.md`,
`docs/types-and-interfaces.md`, website props, `docs/feature-checklist.md`, roadmap 3.3.5 row incl. the two cuts).
Public text never frames this as parity; cite behaviour with file:line. No dev log, no CHANGELOG.

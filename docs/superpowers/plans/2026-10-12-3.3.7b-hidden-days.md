# 3.3.7b Hidden days in every view Implementation Plan

> TDD (superpowers:test-driven-development). Part of `docs/roadmap.md`, release 3.3, item 3.3.7 (part b). Related: #82, #112.

**Goal:** `hiddenDays` (and a new `weekends: false`) hide days in every date-based view, not just the week views.

## The standard (FullCalendar v7.1.1 source, `packages/preact/src/`)
- `weekends: false` adds 0 and 6 to the hidden set (`DateProfileGenerator.ts:397-399`); hiding every day is an error
  (`:410`). Indices are absolute day-of-week (0 = Sunday), independent of the first day of week (`:403`).
- Honoured by day grids, time grids and multi-month (`common/DaySeriesModel.ts:33-58`, `MultiMonthView.tsx:248-259`);
  the visible range is trimmed at its ends (`trimHiddenDays`, `DateProfileGenerator.ts:100-122,412-432`).
- An all-day / day-grid event spanning hidden days draws as one contiguous bar over the visible columns, clamped to the
  nearest visible column; starting on a hidden day gives `isStart: false`, ending on one `isEnd: false`
  (`DaySeriesModel.ts:60-80`, tests `legacy/DayGrid-events.ts:66-79,162-176`). An event entirely on hidden days
  produces no segment.
- Timed events in time grids are sliced per visible column, so hidden days are skipped.
- The title uses the trimmed range (`legacy/titleFormat.ts:155-160`).

## Today in ilamy
`hiddenDays` works only in the week view and the hourly vertical resource week (`features/calendar/types/index.ts`
TSDoc ~386-403). Read how they do it first, and reuse the same mechanism.

## Decisions (record)
- `weekends?: boolean` (default true); false adds Sunday and Saturday to `hiddenDays`. Do not mutate the consumer's
  array (the convention's code does; don't copy that).
- Hiding every day: ignore `hiddenDays` and `console.warn` once (the convention throws; a warning is friendlier and
  keeps the calendar usable — record the deviation).
- Apply to: month view (columns and rows), day view (navigation skips hidden days: prev/next/today land on the nearest
  visible day; FullCalendar's day view does this through its date increment — verify how and cite), resource views of
  every orientation/granularity (week, month), and the header title range. Year view and the agenda plugin: leave
  unchanged and say so (year shows mini-months; agenda is a list).
- `EventSegment.isStart` / `isEnd` (already passed to `renderEvent`) must reflect hidden starts/ends as above.
- Drag/resize/drag-to-create cannot target a hidden day (it has no cell).

## Tests first
Unit: month layout with `hiddenDays=[0,6]` — 5 columns, an event Fri→Mon is one bar over Fri and Mon with isEnd/isStart
correct, an event Sat→Sun produces nothing; a Sat→Tue event starts clamped on Mon with isStart false; week-number per
row still from the row's first visible day; `weekends=false` equals `hiddenDays=[0,6]`; all days hidden → ignored +
warn; day view navigation skips a hidden day; resource month/week; title range trimmed.
e2e: `&weekends=false` month shows 5 columns per row and the right dates; `&hiddenDays=wednesday` (check the harness
param format) in month/day/resource views; dragging across the gap lands on a visible day; existing week-view
hiddenDays specs unchanged.

## Global constraints
No breaking change (unset = today's rendering in every view; week view behaviour unchanged); configured dayjs only; no
`!`, no `any`, `.at()`, named exports, name every condition; unit AND e2e first; revert proof; docs (`docs/time-grid.md`
or the relevant view doc, `docs/types-and-interfaces.md`, website props page, roadmap 3.3.7 row). Public text never
frames this as parity; cite behaviour with file:line. No dev log, no CHANGELOG.

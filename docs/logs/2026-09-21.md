# Development Log - 2026-09-21

## Changes

- **[tooling]**: Biome 2.4.16 → 2.5.14, and the config migrated with
  `biome migrate --write`.
  - `$schema` was pinned at **2.3.8**, four minor versions behind the range and
    two behind what was actually installed. `^2.4.16` already floated to 2.5.13
    locally, so the schema the editor validated against had not matched the
    binary for some time.
  - `linter.rules.recommended: true` → `linter.rules.preset: "recommended"`.
    The old key is deprecated in favour of `preset`, which takes
    `"recommended" | "all" | "none"`; `"recommended"` is the default and enables
    the same set (https://biomejs.dev/reference/configuration/).

- **[tooling]**: The three `examples/*/biome.json` files got the same migration.
  They were at 2.3.8 / 2.3.10 with the deprecated key, and none of them is wired
  to anything: no `@biomejs/biome` dependency, no script that runs it, and the
  root config excludes `examples` outright. An editor opening one of those
  projects still reads the file, so it is worth keeping current, but the bigger
  finding is that they are orphaned config. Separate cleanup.

## Files Modified

- `package.json` - `@biomejs/biome` ^2.4.16 → ^2.5.14
- `biome.json` - schema 2.3.8 → 2.5.14; `recommended: true` → `preset: "recommended"`
- `examples/{astro,nextjs,vite}/biome.json` - same two changes
- `bun.lock` - resolution

## Notes

- **No behaviour change, verified rather than assumed.** The warning breakdown
  is rule-for-rule identical across the upgrade (12 `noExplicitAny`, 2
  `noConsole`, 2 `noNonNullAssertion`, 1 `noAssignInExpressions`, 1
  `noArrayIndexKey`), measured by running the OLD binary against the OLD config
  and the new against the new. Nothing was silently disabled by the `preset`
  rename.
- `bun run format:check` reports no drift, so the formatter's output is
  unchanged on this tree. Worth checking on any Biome bump: a formatter change
  would otherwise land as a diff on unrelated files in someone else's PR.
- The 2.5.x line adds a number of rules, all in the **nursery** group, which is
  opt-in and cannot fail an existing build
  (https://biomejs.dev/internals/changelog/). None were enabled here.
- `biome migrate` is not required for a minor upgrade; it was run because the
  config had drifted, and it is the documented way to pick up a renamed key.
- `examples/nextjs` reports errors under BOTH the old and new version: it lints
  `.next` build output. Pre-existing, not from the migration, and not in CI.
- The version range stays a caret, matching every other devDependency;
  `bun.lock` is what actually pins resolution.
- Gates: `bun run ci` (998 tests), `bun run e2e` (46), Fallow clean, no lint
  errors, no formatting drift.

ilamy Calendar separates **framework-agnostic CSS styling systems** from **framework-specific component UI libraries**. The core stylesheet at `@ilamy/calendar/styles.css` (`@layer ilamy.base, ilamy.theme`) works across React, Vue, Svelte, Solid, Angular, and Vanilla DOM with **zero Tailwind and zero UI-library dependencies** installed.

---

## Layer 1: Styling Systems (CSS — Framework-Agnostic)

Everything in this layer applies across all framework adapters and Vanilla DOM with zero React or UI-library code.

### Default: Layered CSS (`@ilamy/calendar/styles.css`)

Import `@ilamy/calendar/styles.css` once in your app — **no Tailwind installation or `@source` directive is required**:

```ts title="main.tsx"
import '@ilamy/calendar/styles.css'
```

If you use Tailwind CSS v4 (or shadcn/ui), import it **before** `@import 'tailwindcss';` so Tailwind utilities sit in a higher cascade layer:

```css title="globals.css"
@import '@ilamy/calendar/styles.css';
@import 'tailwindcss';
```

#### Design Tokens & shadcn/ui Auto-Bridging

Inside `@layer ilamy.base`, `[data-ilamy-root]` reads `--ilamy-*` tokens that automatically fall back to your page's shadcn variables (`--background`, `--foreground`, `--card`, `--muted`, `--muted-foreground`, `--border`, `--primary`, `--primary-foreground`, `--destructive`, `--radius`, `--font-sans`, and `.dark`), with clean light/dark defaults when no theme is present:

| Token | Bridges shadcn var | Purpose |
|---|---|---|
| `--ilamy-bg` | `--background` | Calendar and cell background |
| `--ilamy-fg` | `--foreground` | Primary text color |
| `--ilamy-surface` | `--card` | Header / resource-header / all-day surface |
| `--ilamy-muted` | `--muted` | View switcher track, hover & non-business tint |
| `--ilamy-muted-fg` | `--muted-foreground` | Secondary labels & outside-month text |
| `--ilamy-border` | `--border` | Grid borders & button borders |
| `--ilamy-primary` | `--primary` | Today badge, active primary buttons, default event bars |
| `--ilamy-primary-fg` | `--primary-foreground` | Text on primary surfaces |
| `--ilamy-danger` | `--destructive` | Current-time indicator |
| `--ilamy-radius` | `--radius` | Border radius for controls, inputs & event bars |
| `--ilamy-font` | `--font-sans` | Root font family |

Override any `--ilamy-*` token on `[data-ilamy-root]` or a wrapper element to theme the calendar without writing component overrides.

### Slot Overrides (`[data-ilamy-slot="..."]`)

All built-in rules in `@layer ilamy.base` and `@layer ilamy.theme` are wrapped in `:where(...)` (zero specificity) inside CSS layers. Any normal selector targeting `[data-ilamy-slot="..."]` overrides them cleanly **without `!important`**:

```css
[data-ilamy-slot='event-bar'] {
  border-radius: 9999px;
  font-weight: 600;
}

[data-ilamy-slot='cell'][data-non-business='true'] {
  background-color: #f9fafb;
}

[data-ilamy-slot='dialog'] {
  border-radius: 0.75rem;
}
```

Semantic slots include `root`, `header`, `toolbar`, `nav-group`, `arrow-group`, `nav-button`, `view-switcher`, `view-button`, `grid`, `grid-scroll`, `month-header`, `day-header`, `resource-header`, `all-day-row`, `grid-row`, `cell`, `event-bar`, `now-indicator`, `more-link`, `dialog`, `popover`, `input`, `textarea`, `select`, and `checkbox`.

### Structural-Only CSS, `unstyled`, and `slotProps`

For fully custom visual chrome while keeping structural layout (flex/grid geometry, sticky headers/gutters, and scrolling), import `@ilamy/calendar/styles/base.css` (`@layer ilamy.base`, zero visual chrome) and/or pass `unstyled` with `slotProps`:

```tsx
import { IlamyCalendar } from '@ilamy/calendar/react'
import '@ilamy/calendar/styles/base.css'

<IlamyCalendar
  events={events}
  unstyled
  slotProps={{
    root: { className: 'my-calendar' },
    header: { className: 'my-header' },
    cell: { className: 'my-cell' },
    eventBar: { className: 'my-event' },
    resizeHandle: { className: 'my-resize-handle' },
  }}
/>
```

### StyleX (`@ilamy/calendar/styles/stylex`)

`@ilamy/calendar/styles/stylex` is a **framework-agnostic CSS styling system** (an alternative to Tailwind or plain CSS, with zero React dependency). It exposes `--ilamy-*` token presets (`createStylexCalendarTheme`, `stylexCalendarTheme`, `stylexCalendarDarkTheme`) and helpers (`stylexSlot`, `createStylexSlotProps`) for merging compiled `stylex.props(...)` outputs across React, Vue, Svelte, Solid, Angular, and Vanilla DOM:

```tsx
import * as stylex from '@stylexjs/stylex'
import { IlamyCalendar } from '@ilamy/calendar/react'
import { createStylexCalendarTheme } from '@ilamy/calendar/styles/stylex'
import '@ilamy/calendar/styles.css'

const styles = stylex.create({
  eventBar: { borderRadius: 9999 },
})

const stylexTheme = createStylexCalendarTheme({
  mode: 'light',
  slots: { eventBar: stylex.props(styles.eventBar) },
})

<IlamyCalendar events={events} {...stylexTheme} />
```

## Layer 2: Component UI Libraries (Framework-Specific)

### Zero-Dependency Native HTML Defaults

Out of the box, `@ilamy/calendar` ships **zero UI-library dependencies** — no Radix UI, no icon packages, no CVA, and no Tailwind runtime helpers. Built-in dialogs, popovers, buttons, inputs, textareas, selects, and checkboxes render using semantic native HTML elements (`<dialog>`, `<button>`, `<input>`, `<select>`, etc.) styled by `@ilamy/calendar/styles.css` across both React and Vanilla DOM.

### Bring Your Own Primitives (`components` prop in React)

In React (`@ilamy/calendar/react`), swap any interactive primitive (`Button`, `Dialog`, `Popover`, `Input`, `Textarea`, `Select`, `Checkbox`) via the `components` prop. Because `@ilamy/calendar` bundles zero Radix, your own design system primitives work seamlessly without version conflicts — whether you use **shadcn/ui with Base UI**, **shadcn/ui with Radix**, React Aria, or Chakra UI:

```tsx
import { IlamyCalendar } from '@ilamy/calendar/react'
import '@ilamy/calendar/styles.css'
import { Button } from '@/components/ui/button'
import { Input } from '@/components/ui/input'
import {
  Dialog,
  DialogContent,
  DialogHeader,
  DialogTitle,
} from '@/components/ui/dialog'

<IlamyCalendar
  events={events}
  components={{
    Button,
    Input,
    Dialog: ({ open, onOpenChange, title, children }) => (
      <Dialog open={open} onOpenChange={onOpenChange}>
        <DialogContent>
          {title ? (
            <DialogHeader>
              <DialogTitle>{title}</DialogTitle>
            </DialogHeader>
          ) : null}
          {children}
        </DialogContent>
      </Dialog>
    ),
  }}
/>
```

### Material UI (`@ilamy/calendar/react/mui`)

`@ilamy/calendar/react/mui` is a **React component library integration** that bridges your MUI `Theme` (`useTheme()`) directly into `--ilamy-*` CSS custom properties and provides `@mui/material` primitives (`Button`, `TextField`, `Checkbox`, `Dialog`, `Select`, `Popover`) via `muiCalendarComponents`:

```tsx
import { IlamyCalendar } from '@ilamy/calendar/react'
import { useMuiCalendarTheme } from '@ilamy/calendar/react/mui'
import '@ilamy/calendar/styles.css'

export function MuiCalendar({ events }) {
  const muiTheme = useMuiCalendarTheme()
  return <IlamyCalendar {...muiTheme} events={events} />
}
```

Outside a MUI `<ThemeProvider>`, use `createMuiCalendarTheme({ theme })` directly.

## Headless Core (`@ilamy/calendar`)

Building a completely custom calendar UI? Import the zero-framework, zero-CSS engine directly from `@ilamy/calendar`:

```ts
import {
  createCalendarController,
  buildMonthViewModel,
  buildTimeGridViewModel,
  isRangeWithinBusinessHours,
} from '@ilamy/calendar'

const controller = createCalendarController({
  events,
  timezone: 'America/New_York',
  initialView: 'week',
})
```

## Cells During a Drag

While an event is dragged over the calendar, the grid wrapper carries `data-dragging="true"`. Day cells and time slots use it to suppress hover tints during drags.

# Development Log - 2026-09-14

## Changes

- **[resource day view]**: Fixed #280. `useProcessedWeekEvents` bucketed its map by calendar day and keyed it with `YYYY-MM-DD`, ignoring the `gridType` it was given. A resource day view in horizontal orientation draws 24 hour columns from one date, so all 24 collapsed onto a single entry and every cell was handed the whole day's events. The visible result was `+N more` on every cell of the row, including hours holding nothing, and clicking any of them opened a dialog listing the whole day.

- **[resource day view]**: The map now buckets by the column's own unit and is keyed by `columnKey(day, gridType)`, exported so the row that reads it uses the same definition rather than a second copy. Measured through the real view, seven one-hour events with `dayMaxEvents={4}`: before, 24 cells, 96 height spacers and 24 indicators; after, 24 cells, 7 spacers and no indicators. The over-long list was also sizing each cell's height placeholders, which is the row-height symptom the reporter noted, and it is resolved by the same change.

- **[types]**: `dayMaxEvents`'s doc comment claimed a default of 3; `DAY_MAX_EVENTS_DEFAULT` is 4. The website's prop table already said 4.

## Notes

The report was unusually good: it located the defect in the minified bundle, named the mechanism, and proposed two fixes. Both were viable. Bucketing by unit was chosen over skipping `precomputedEvents` for hour columns because it keeps the precomputation for every grid rather than dropping it for one, and because a map whose key does not identify its column is the actual defect.

A revert test nearly produced a false negative here. Changing only the hook's key left the row looking up by the old one, so the lookup missed, `precomputedEvents` came through undefined, and the cell fell back to its own correct query — which is the reporter's *other* suggested fix. The "before" numbers only became trustworthy after stashing both files together.

Views that were never affected, confirmed by the suite staying green: resource week (its columns carry `days` arrays and build cells without `precomputedEvents`), month grids (one column per day, so the date key is already unique), and the vertical orientations (a different engine with no overflow indicator).

# Development Log - 2026-10-12

## Changes

- **[docs]**: Added the roadmap (now `docs/roadmap.md`), built from a sweep of the v3.2.1 code, established calendar conventions and all 109 issues. Shape: two additive minors (3.3 editing and time axis; 3.4 data, control, plugin-contract hooks, deprecations), the breaking 4.0 (Temporal migration, ISO dates, optional built-ins moved to plugins, removals), then 4.1 (scheduling rules, drag ecosystem), 4.2 (scheduler) and 4.3 (views, a11y, RTL, print, interop). Patches for bug fixes ship from `main` at any time.
- **[docs]**: The plan keeps the core small: a feature is a plugin when the public contract plus a small general hook can carry it. Six hooks are added in 3.4 for that.
- **[process]**: The plan's Delivery process runs the work without the owner in the loop: the main session manages Sonnet engineers (worktrees), persona QA agents and the code-review gates, and does the final verification itself. `AGENTS.md` gains a scoped exception: for the roadmap program the manager may commit on `roadmap/*` branches, push and open PRs after final verification; the owner merges. Never `main`, never local-only commits.
- **[docs]**: `docs/api-parity-checklist.md` points to the roadmap.
- **[docs]**: The roadmap is renamed to `docs/roadmap.md` and framed as ilamy's own plan; FullCalendar stays only where it is cited as the reference for a specific behaviour (CLAUDE.md's standard rule). Branches use `roadmap/*`. Recorded two spec decisions: 3.3.1 adds no `oldEvent` field (`EventsChange.event` already is the pre-change event), and D8 (`editable` defaults to true in 3.x).
- **[e2e]**: The harness port comes from `E2E_PORT` (default 4200), so agent worktrees can run e2e at once. Without it a second worktree silently reused the first one's server (`reuseExistingServer` is true locally) and tested the wrong code. CI is unchanged.
- **[docs]**: README and website claims audited against v3.2.1 (plan item 3.3.0). Fixed: resize (does not exist), overlap prevention (does not exist), "100% test coverage" (measured 90.24% lines in the calendar package), "100+ locales" (any dayjs locale the consumer imports), timezone wording, minified size (126,755 bytes; ~40 KB gzipped unchanged), dark mode (comes from the consumer's tokens), and a performance claim with no benchmark behind it. Added the drag-to-create plugin to the plugin list.
- **[tooling]**: `.claude/worktrees/` is gitignored. Agent worktrees are full repo copies; Biome reads `.gitignore` (`vcs.useIgnoreFile`) and was linting them as nested root projects, failing `bun run format:check` in the main checkout.
- **[feature]**: Edit permissions (roadmap 3.3.2). New props `editable` (default `true`), `eventStartEditable` and `eventAllow(dropInfo, draggedEvent)`; per-event `editable`/`startEditable`. Resolution follows the FullCalendar convention: within a level the specific flag beats `editable`, and the event beats the calendar (`event-ui.ts:61-94`, v7.1.1). `eventAllow` is asked once per placement and again at drop, so a fast release cannot slip past it. A refused placement draws no preview and no drop tint, only the not-allowed cursor; this now applies to disabled cells too. When nothing can move, no dnd-kit context mounts (the old `disableDragAndDrop` path), and a bar that cannot move carries no drag attributes, so screen readers get no drag instructions for it. `disableDragAndDrop` is a deprecated alias of `editable={false}`. `eventDurationEditable` arrives with resize (3.3.3).
- **[feature]**: Change info (roadmap 3.3.1). `EventsChange` gains `delta` (`{ days, milliseconds }`: whole calendar days plus wall-clock time of day, on every update) and `revert()` (undoes the action's rows in the calendar's store, recurring scopes included; fires no callbacks; a second call is a no-op). A timed event dropped on the all-day row is measured from its day start (FullCalendar `EventDragging.ts:454`, v7.1.1). A drop that leaves start, end, all-day and resource unchanged now commits nothing and fires no callbacks (it used to fire an update, and opened the recurring scope dialog). `EventsChange.event` is already the pre-change event, so no `oldEvent` field is added.
- **[fix]**: `delta` read an hour short for a drop in the skipped spring hour: the drop builds a Dayjs that keeps the pre-change offset, so its clock read 02:30 for the instant that is 01:30. `toEventDelta` re-zones both dates from their instants. The grid cell for that hour still disagrees with where a drop lands; filed as a separate task.
- **[feature]**: Formats (roadmap 3.3.6). New props `slotHeaderFormat`, `eventTimeFormat`, `dayHeaderFormat`, `titleFormat` (`Intl.DateTimeFormatOptions`, rendered with the calendar's locale and zone; v7 names, `slotLabelFormat` is the old one), `displayEventTime`, `displayEventEnd`. Unset options render exactly as before. A set `dayHeaderFormat` is the whole header text (week, month, resource and day view headers) and truncates with an ellipsis and a `title`. 12/24-hour follows the locale unless `timeFormat` is passed explicitly. An overnight range is written as two times, a same-day range in the locale's own range format. Intl formatters are cached by locale, zone and options.
- **[feature]**: Display toggles (roadmap 3.3.7a). `allDaySlot` (default true; false removes the all-day row in day, week and vertical resource views, and all-day events are not shown there), `nowIndicator` (default true, roadmap D3), `weekNumbers` (unset keeps today's week-header number; true adds a number to each month row; false hides them everywhere, the daily resource-week header included), `weekNumberCalculation` (`'local'` = dayjs `week()` as today, `'ISO'`, or a function; `firstDayOfWeek` still decides the first day). `scrollTime` and `scrollToNow` now scroll to the exact minute (FullCalendar `TimeGridLayout.tsx:285-296`, v7.1.1); they used to floor to the hour, a documented contract that moved deliberately. Minutes or seconds above 59 are rejected.
- **[feature]**: Event resize (roadmap 3.3.3, closes #93). Handles on the end edge (and the start edge with `eventResizableFromStart`), each its own dnd-kit draggable through the existing drag preview, refusal and commit path. Time grids snap to the slot, day grids to whole days; a resize stays in its grid (no all-day/time-grid crossing) and never changes the resource; refusal (`eventAllow`, `isCellDisabled`, business hours) is judged on the event's own lane. New `eventDurationEditable`, per-event `durationEditable`, `EventsChange.endDelta`. Single-day timed events in month (dots) are not resizable. On touch-only devices there are no handles until event selection exists (the convention resizes only a selected event on touch, `EventResizing.ts:86-88`, v7.1.1).
- **[fix]**: Vertical event bars sat 4-7px below their slot: `AnimatedSection` is inline-block and sat on the text baseline. `align-top` on the bar fixes it; resize depends on it.
- **[feature]**: Visible hours (roadmap 3.3.4). `slotMinTime` / `slotMaxTime` (`'HH:mm'` up to `'24:00'`, end exclusive) narrow every hour grid (day, week, both resource orientations). `hideNonBusinessHours` narrows within the window; if they do not overlap, the window wins with one warning. Invalid values fall back to the whole day with a warning. Sub-hour bounds show the whole hour row. Past-24:00 windows are cut.
- **[fix]**: The horizontal hour layout clamped events outside the visible columns to the edge columns (or drew them past the grid) instead of dropping them, and measured week-mode columns from the first one; it now slices by the columns an event overlaps, end exclusive (FullCalendar `DayTimeColsSlicer.ts:7-22`, v7.1.1). Reachable before via `hideNonBusinessHours`.
- **[fix]**: `getDayHours` built hour rows as `startOfDay.hour(i)`, which on a clock-change day carries a stale offset when the machine zone has clock changes; rows are now anchored from a wall-clock string in the calendar's zone (the pattern `calculateDropTimes` uses). Events on DST days no longer land a row off in windowed grids, and a drop now lands on the cell's own instant. A first attempt changed the shared `toWallClockUtc` helper instead; an audit of every caller showed it regressed cross-zone cases, so it was reverted.
- **[feature]**: Hidden days in every view (roadmap 3.3.7b). `hiddenDays` now applies to month, week, day and every resource arrangement; new `weekends` (default true; false hides Saturday and Sunday, the consumer's array is not mutated). Day view navigation skips hidden days in the direction of travel (FullCalendar `DateProfileGenerator.ts:279-295,450-457`, v7.1.1). Bars over hidden days are clamped to the drawn columns, with start/end affordances off when the start/end is hidden; an event wholly on hidden days draws nothing (`DaySeriesModel.ts:60-80`). Hiding every day is ignored with a dev warning. `onDateChange`/`currentRange` stay untrimmed in 3.x (4.0 candidate). Year view and agenda unchanged.
- **[feature]**: Async events (roadmap 3.3.8). `events` may be `(info, { signal }) => Promise<Event[]>`, called with the visible grid range (month padding days included, end exclusive) and the zone. `lazyFetching` (default true) refetches only when the range leaves the last fetched one or the zone changes (FullCalendar `reducers/eventSources.ts:125-134`, v7.1.1); a superseded fetch is aborted and its late result ignored; `loading(isLoading)` fires on transitions; a failure keeps the shown events, calls `onEventsError` and retries on the next navigation; `refetchEvents()` on the context. With a fetcher a refetch shows exactly what it returns (no surviving client-only rows; ilamy has one source). A new fetcher identity does not refetch (an inline fetcher would loop); call `refetchEvents()` when the query changes.
- **[feature]**: Slot and snap sizes (roadmap 3.3.5, closes #101 and #138). `slotDuration` accepts any divisor of 60 (else 60 with a warning; 15/30/60 render identically). New `snapDuration`: drag, resize and drag-to-create snap finer than the cell, in vertical grids and the horizontal resource timeline, by the pointer's live position inside the cell; a snap that does not divide the cell falls back to the cell (FullCalendar `TimeGridCols.tsx:162-172`, v7.1.1); resolved per cell, so the hourly horizontal timeline can snap finer than `slotDuration`. Pure snap math moved to `@ilamy/utils/helpers`, shared by core and the drag-to-create plugin; the cell attributes plugins may read are documented in `docs/writing-plugins.md`. `slotHeaderInterval` and slots longer than an hour are cut.
- **[feature]**: Ref API (roadmap 3.3.9). `IlamyCalendar` (and the deprecated `IlamyResourceCalendar`) take a `ref` (React 19 ref-as-prop, no `forwardRef`; https://react.dev/reference/react/useImperativeHandle). `ref.current` is one stable handle with the same API as `useIlamyCalendarContext()` (methods delegate to the latest API, values are getters) plus `scrollToTime(time)`, which acts on the current view only. A stable handle matters: republishing it per render made a state-setting callback ref loop forever.
- **[fix]**: In a multi-day horizontal resource timeline, scrolling to the last visible hour (the `scrollTime` prop too) landed at the end of the range instead of the first day; the clamp now stays within the first day.
- **[fix]**: With a snap finer than the cell, the drag/resize preview stayed on the slice where the pointer entered the cell while the drop used the live pointer: dnd-kit fires `onDragOver` only when the hovered cell changes. The preview now also updates on `onDragMove`, bounded by `isSameDrop`, so it commits once per slice change (3 commits for an 86-move slide across one cell).
- **[feature]**: Async resources (roadmap 3.3.10). `resources` may be `(info, { signal }) => Promise<Resource[]>`, fetched once by default (`refetchResourcesOnNavigate` refetches on leaving the fetched range); `resourcesSet` fires when the list's content changes (compared by content: `businessHours` by value, `data` one level deep, so inline literals don't loop); `onResourcesError`; `refetchResources()` on the context; one aggregate `loading` for events and resources. A resource function makes it a resource calendar from the first render (zero lanes until the list arrives, no layout flash). The events fetcher is generalised into one `use-range-fetcher` hook.
- **[test]**: The sticky-title drag-mirror spec (#290) was flaky on `main` (17/50): its grab point mixed viewport and page coordinates, landed in dnd-kit's auto-scroll zone, and the drag sometimes ended outside the scroller (no cell, no mirror). It now grabs the middle of the bar's visible part; assertions unchanged. 100/100 after the fix.
- **[scope]**: Narrowed before release (owner/manager decision on cost vs need): `slotDuration` stays `15 | 30 | 60` (the same type as before 3.3; 1-12 minute slots only multiplied cells, droppables and layout work), `snapDuration` is `15 | 30` and applies only when finer than and dividing the cell (still covers #101), and `weekNumberCalculation` is `'local' | 'ISO'` (the function form had no demand).

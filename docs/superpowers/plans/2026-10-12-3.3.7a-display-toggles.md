# 3.3.7a Display toggles Implementation Plan

> TDD (superpowers:test-driven-development). Part of `docs/roadmap.md`, release 3.3, item 3.3.7 (part a; hidden days
> in every view is part b, later). Related: #37.

**Goal:** Consumers can hide the all-day row, turn the now indicator off, show or hide week numbers (including in
month view), choose how week numbers are counted, and scroll to a time with minutes.

## The standard (FullCalendar v7.1.1 source, `packages/preact/src/`)
- `allDaySlot` default true; false removes the all-day lane; all-day events are then not shown in time-grid views
  (`timegrid/index.ts:13`, `TimeGridLayoutNormal.tsx:264`, `timegrid/AllDaySplitter.ts:19-33`).
- `nowIndicator` default false (`options.ts:496`); only time grids show it.
- `weekNumbers` default false (`options.ts:493`). Month (multi-row day grid): number inline in each week row from the
  row's first date (`DayGridRows.tsx:137`, `DayGridRow.tsx:140,216-238`). Time grid: in the time-axis corner of the
  header (`TimeGridLayoutNormal.tsx:195`).
- `weekNumberCalculation` default `'local'` (locale's week rules), `'ISO'` (Monday, first week has the 4th), or a
  function `(date: Date) => number` (`env.ts:24,66-77`). An explicit first day of week overrides the locale's dow.
- `scrollTime` minutes honoured as a continuous fraction (`TimeGridLayout.tsx:285-296`).

## Decisions (record; defaults reproduce today)
- `allDaySlot?: boolean` default true. False hides the all-day row in day, week and vertical resource views; all-day
  events are then not shown there (convention). Month/year/agenda unaffected.
- `nowIndicator?: boolean` default **true** (ilamy always shows it today; the convention's default is false — roadmap
  decision D3, revisit in 4.0).
- `weekNumbers?: boolean` — **unset keeps today's behaviour exactly** (week number in the week view / resource-week
  headers, none in month). `true` additionally shows numbers in month view rows; `false` hides them everywhere.
- `weekNumberCalculation?: 'local' | 'ISO' | ((date: Date) => number)` default `'local'`: check what ilamy computes
  today (dayjs `week()` with `firstDayOfWeek`?) and make `'local'` reproduce it exactly.
- `scrollTime` and `scrollToNow` scroll to the exact minute (today minutes are floored to the hour) — a behaviour fix:
  confirm in the code and docs that the current floor is not documented as intended; if it is, keep it and stop to
  report.

## Where (verify): `components/current-time-marker.tsx` + its users, the all-day row (`components/all-day-row/`) in
week/day/resource vertical views, `components/views/week.tsx:58` and resource week headers (week number), month view
rows (`components/views/month.tsx` / horizontal grid row), the scroll-to-time hook (`use-scroll-to-time`), types +
context flow. Harness params `allDaySlot`, `nowIndicator`, `weekNumbers`, `weekNumberCalculation` (`local`/`ISO`).

## Tests first
Unit: each option on/off; unset renders exactly as before; ISO vs local week numbers for a date where they differ
(e.g. 2025-12-29: ISO week 1 of 2026; US local week depends on `firstDayOfWeek` — compute and assert both); a
function calculator is used; scroll offset for '08:30' is between the 8 and 9 rows proportionally.
e2e: `&allDaySlot=false` week view has no all-day row and an all-day scenario event is not shown; `&nowIndicator=false`
no now line; `&weekNumbers=true` month view shows a number per row; `&weekNumbers=false` week view shows none;
`&scrollTime=08:30` lands between 8 AM and 9 AM.

## Global constraints
No breaking change; configured dayjs only; no `!`, no `any`, `.at()`, named exports, name every condition; unit AND e2e
first; revert proof; docs (`docs/time-grid.md`, `docs/types-and-interfaces.md`, website props page,
`docs/feature-checklist.md` tick `allDaySlot`). Public text never frames this as parity; cite behaviour with
file:line. No dev log, no CHANGELOG.

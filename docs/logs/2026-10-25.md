The published 3.3.0 tarball was compared with a fresh build of the same commit. They match except that the `@ilamy/ui` copy of the dayjs configuration came from a stale `packages/utils/dist` (built 10 October), so it lacks #378's line. ## Changes (instructions)

- **[agents]**: `AGENTS.md` (read as `CLAUDE.md`) gains a Hard Rule: a feature is not done, and a release not ready, until it has been exercised in `apps/demo` with its default settings and seed events, and after a deploy on https://ilamy.dev/demo, with a real pointer and a probe shown to be able to fail. The Releases section repeats the gate. The example is 3.3.0's resize: it passed every harness spec and QA round, and on release day looked broken in the demo. It was not; the demo's default business hours refused the drop on closed cells (release day was a Sunday), and a first investigation's flawed probes reported a bug that did not exist. Retracted here and in the example: resize works.

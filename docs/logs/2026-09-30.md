# Development Log - 2026-09-30

## Changes

- **[sticky titles]** (#290, reported on PR #292): A long event's title now also stays in view when the PAGE scrolls, not only the calendar's own scroller.
  - The report: a 1000px week in the demo, with the page scrolled. The regular grid's header sits outside the calendar's scroller, so `stickyViewHeader` pins it to the window, and the tall events slid under it with their titles.
  - A sticky element only responds to its nearest scroll container (MDN, `position: sticky`), which for the title is the grid's own. So CSS alone could not follow the page.
  - Measured before the fix: page scrolled 300px, grid scroll 0, header covering 0 to 73px, title at 1px.
- **[useStickyInsets]**: The insets are now how far into the viewport the reader cannot see, measured as positions against the viewport's edges rather than as sizes. The furthest of these wins:
  - The grid's own marked sticky column and header, now looked up in the whole grid (`rootRef`), so a regular grid's header outside the scroller counts.
  - That header once it is pinned to the window.
  - The window's own top-left, and every clipping ancestor (overflow `hidden`, `scroll`, `auto`, `overlay` or `clip`; found once per subscription).

  It re-measures on `scroll` of the window and each such ancestor, and on window `resize`. Listeners are passive, coalesced to one measurement per animation frame; a frame requested from a scroll event runs before that frame paints.
- **[beyond FullCalendar]**: FullCalendar pins headers to the window only with `height: 'auto'` (`stickyHeaderDates: 'auto'`, https://fullcalendar.io/docs/stickyHeaderDates), where it has no inner scroller and `fc-sticky` follows the page for free. With a fixed height its titles follow only its own scroller. We follow the page in both cases; the maintainer chose this (option 1 of 3) over matching FullCalendar by un-pinning the header. The website docs state the difference.

## Changes (website dev: dayjs locales)

- **[website]**: Fixed `dev:website` failing to hydrate the playground with "`dayjs.js` does not provide an export named 't'".
  - The playground imports all 143 dayjs locales (`packages/playground/src/lib/dayjs-locales.ts`) from inside a React island, which Astro's first dependency scan does not crawl. The locales were found only when the browser requested that module.
  - Finding them forced a second pre-bundle, which rewrote `dayjs.js` to also export `t` (the CommonJS wrapper every locale imports). The dev server kept serving the first run's `dayjs.js` under the same `?v=` URL, which has only `export default`.
  - Reproduced from a cleared `.vite` cache: disk `dayjs.js` had `export { require_dayjs_min as t }`, the served one did not.
  - Fix: `vite.optimizeDeps.include: ['dayjs', 'dayjs/locale/*.js']` in `apps/website/astro.config.mjs`, so the first run bundles them all. Vite documents the trailing glob for exactly this: "avoids repeatedly pre-bundling new deep imports as they're discovered" (https://vite.dev/config/dep-optimization-options#optimizedeps-include, marked experimental).

## Changes (current hour in time grids)

- **[time grids]**: The vertical grids' time gutter now marks the hour holding now, as the horizontal resource timeline's header row already did. This covers the regular week and day views and the vertical resource week (hourly) and day views; the maintainer asked for parity.
  - An hour gutter labels every day column at once, and its hours are built on the view's date, not today. So `gutterColumn` takes `showsToday` from the caller (`isToday(date)` in day views, `visibleDays.some(isToday)` in week views) and marks by hour of day.
- **[both axes]**: The marked label carries `aria-current="time"` ("the current time within a set of times", MDN), on the horizontal header row too. Specs assert on that attribute rather than on classes.
- **[constants]**: The two axes share `CURRENT_HOUR_LABEL_CLASS` (`bg-blue-50 text-blue-600 font-medium`).
- **[AGENTS.md]**: The Code Quality rule now says: name every condition, boolean operand and computed argument, prop or JSX attribute before use, and pass the name, not the expression. Added at the maintainer's request, after this change first inlined them.

## Changes (timeline exact time)

- **[resource timeline]**: An hour axis now draws each event at its exact times instead of rounding it out to whole hour cells.
  - Reported before v3.1.0: the playground's "Morning Yoga Class" (10:xx-12:xx, minutes from page load) drew across three hour cells. Dragging it seemed to cut an hour, because the mirror showed its true two.
  - FullCalendar's timeline places events exactly: v6.1.19 `computeDateSnapCoverage` "add[s] the remainder" within a snap, and v7.1.0 `computeMsSlotCoverage` interpolates within the slot. ilamy's vertical grid already did.
  - Day axes (month rows, all-day rows) still draw whole days, as FullCalendar's daygrid does.
- **[layout]**: `computeBarEdges` in `lib/layout/horizontal.ts` measures each end inside its own column, so it holds where the axis skips hours. Row stacking is unchanged (whole cells). A zero-length event keeps its whole column.
- **[geometry]**: Horizontal bars get `minWidth: calc(var(--spacing) * 8)`, matching FullCalendar's timeline `eventMinWidth` ("the minimum width an event is allowed to be", 30px default).
  - It is on the consumer's own `--spacing` scale, like the `min-w-20` hour columns (Tailwind: `min-w-<n>` is `calc(var(--spacing) * <n>)`). So it stays 40% of the minimum column whatever theme or root font size.
  - The bar and the drag mirror share it.
- **[AGENTS.md, review-conventions, testing-guide]**: The "never create new test files / functions" rule was reworded to its intent, at the maintainer's direction: one test file per unit (never split `component.test.tsx` into `component.someFunction.test.tsx`; a unit with no tests gets a new co-located file), and no parallel function next to one that already does the job.

## Notes (timeline exact time)

- Revert-proofed:
  - Forcing whole columns back fails both e2e specs, with the reported symptom exactly: bar 239px (3h) vs mirror 158px (2h). It also fails 4 unit tests.
  - Without `minWidth` the five-minute bar is 3px and both new checks fail.
- **Retracted:** a suspected timezone bug. A probe with the calendar in Vancouver and the browser in UTC moved an event 7 hours on a one-hour drag. It was dnd-kit auto-scroll: the probe used a 1400px calendar in a 900px window. The same drop through the real UI lands correctly in day and week views. That spec is kept as the only coverage of drops with the two zones apart.
- **Kept as is, by the maintainer's call:** a drop re-anchors the start to a slot boundary (10:27 dropped one hour later lands at 11:00). FullCalendar moves by a delta and would keep 11:27.
- **Retracted:** a suspected split-business-hours bug. Calling the layouts directly with gapped columns (9, 10, 11, 14, …) drew a 14:00 event at 16:00, but the calendar never builds such columns. `getViewHours` keeps everything from the earliest business start to the latest end, so hidden hours never leave a gap. Two e2e specs through the real UI placed the event correctly and were removed with the harness change they needed.
